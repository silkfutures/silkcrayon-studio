# V20.4.2 — Availability transition fix

Includes all V20.4.1 Staff Edit + Test Delete changes.

## Booking availability
- Fixes the transient `Invalid availability request` seen immediately after changing session type.
- The root cause was an intermediate React state where the new service could be paired with the previous service's duration (for example Full Day + 60 minutes).
- Service and valid default duration are now changed atomically.
- Availability requests are only sent when the duration is valid for the selected service.
- Previous in-flight availability requests are aborted and stale responses are ignored.
- Slot selection and stale slot lists clear immediately while the new diary is loading.
- The UI shows `Checking the diary…` during a legitimate transition rather than surfacing a false error.
- Full Day remains 480 minutes and the existing slot generator enforces `start + 480 <= 21:00`, so the latest valid start is 13:00.

## Required SQL
If you have NOT deployed V20.4.1 yet, run `supabase/v20-4-1-staff-contact-fields.sql` once before deploying V20.4.2.
