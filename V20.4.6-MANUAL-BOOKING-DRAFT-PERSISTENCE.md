# Silkcrayon Studio OS V20.4.6 — Manual booking recovery + draft persistence

Includes all V20.4.5 fixes.

## Notification constraint error
V20.4.5 added the manual-booking notification types to the database constraint:
- `admin_booking_confirmation`
- `admin_booking_confirmation_sms`
- `manual_booking_payment_link`
- `manual_booking_payment_link_sms`

It also makes notification-log failures non-fatal so a successfully-created booking is not presented as a failed booking solely because logging failed.

## Manual booking draft persistence
The DM / phone booking form now autosaves its draft in the browser while you work.

Saved:
- artist/customer
- date
- start time
- hours
- session value
- assigned engineer
- payment method
- session note
- policy-confirmed checkbox

If you move to another Studio OS tab/page and come back, the form restores automatically.
The draft is cleared only after a successful booking or when you press **Clear draft**.

## IMPORTANT after seeing the old notification_log error
The booking row may already have been created before the notification failed.
Check the calendar / artist profile before retrying the same date and time.

## SQL
Run:
`supabase/v20-4-5-manual-booking-notification-types.sql`

This migration is idempotent and includes the staff email/phone/photo fields too.
