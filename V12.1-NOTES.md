# V12.1 — change-request workflow + mobile freshness

## Session changes
Customers can no longer move a booking themselves.
They can request an available alternative slot until 48 hours before the session.
The original session remains confirmed until an owner approves the request.

When a request is submitted:
- owner receives an email
- assigned engineer receives an email
- customer receives a request-received email
- request appears at the top of the owner dashboard

Owner can Confirm change or Decline.
Approval re-checks that the requested slot is still available before moving anything.
Customer and engineer are emailed after the decision.

## Mobile update issue
V12.1 also fixes stale installed/PWA pages:
- service worker version bumped to v12.1
- service worker registration bypasses HTTP cache
- active clients reload automatically when a new service worker takes control
- navigations use network-first/no-store
- `/sw.js` is served with no-cache/no-store

## Deploy
1. Run `supabase/v12-1-change-requests.sql`
2. Add optional Vercel env `CUSTOMER_CHANGE_REQUEST_CUTOFF_HOURS=48`
3. Upload/deploy
4. On an iPhone that still shows an old version, fully close and reopen the saved app once after deployment. The new service worker should then take over and future releases should refresh automatically.
