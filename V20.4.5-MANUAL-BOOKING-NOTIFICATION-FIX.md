# Silkcrayon Studio OS V20.4.5 — Manual booking notification fix

Includes all V20.4.4 changes.

## What caused the error
The DM / phone booking route already used these notification types:
- `admin_booking_confirmation`
- `admin_booking_confirmation_sms`
- `manual_booking_payment_link`
- `manual_booking_payment_link_sms`

The live `notification_log_notification_type_check` constraint did not include them, so the booking could be created and then the notification log insert failed.

## Fix
- Adds all four manual-booking notification types to the live constraint.
- Makes email/SMS notification-log failures non-fatal so a successful booking is never presented as a failed booking solely because logging failed.
- Keeps the manual booking/customer notifications working.
- Normalises manual booking customer links to `https://silkcrayon.com` rather than the old Vercel hostname.

## Important before retrying the booking that produced the error
The booking row is created before notifications are sent. Check Studio OS / the artist profile/calendar first. The failed attempt may already exist. Do not create the same booking twice.

## SQL
Run:
`supabase/v20-4-5-manual-booking-notification-types.sql`

This SQL is idempotent and also includes the current staff email/phone/photo fields, so it is safe whether or not the V20.4.3 staff SQL was already run.
