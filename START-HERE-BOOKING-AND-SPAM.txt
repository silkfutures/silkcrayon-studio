SPAM PROTECTION
The example came from the artist-support application. Unlike general enquiries, that endpoint previously lacked honeypot/timing/content checks and only limited each IP+email combination. Changing email addresses could bypass that limit.

Shared server checks now cover general/project/call enquiries, artist support, public mixing requests, booking checkout, hour packs/gifts, newsletter signup and customer login-link requests. They include a hidden bot trap, signed expiring form tokens, minimum elapsed time, replay protection using the existing database rate limiter, a shared per-IP limit, an email limit across IP addresses, origin checks, email and length validation, and existing spam-pattern checks for enquiries. Rejections happen before writes, email sends or AI call preparation. Ordinary forms show errors instead of pretending an enquiry was received. Login failures redirect back to the login page.

The existing authenticated staff/customer forms and private-token review/upload routes retain their access controls. Payment webhooks are not public forms and are unchanged. Existing spam records have not been deleted.

No CAPTCHA account or new environment variable is required for the baseline checks: the server uses FORM_SECURITY_SECRET if supplied, otherwise its existing SUPABASE_SECRET_KEY or SUPABASE_SERVICE_ROLE_KEY. These keys never go to the browser. The existing consume_api_rate_limit database function is required (already used by the previous website); protection fails closed if unavailable. If your previous forms already worked, no database migration is expected. The existing SQL definition is in supabase/v20-2-6-release-hardening.sql.

No system is completely spam-proof. These controls block simple/direct scripts and limit repeat abuse, but signed tokens prove a form was loaded, not that the visitor is human. A determined bot can fetch fresh tokens and use multiple addresses/IPs. A managed CAPTCHA can be added if abuse persists. Layered controls follow OWASP guidance: https://cheatsheetseries.owasp.org/cheatsheets/Bot_Management_and_Anti-Automation_Cheat_Sheet.html
